# UI action and backend coverage

This inventory records the current UI paths, their persistence boundary, and the reason a visibly present action may be unavailable in the local development setup. The workspace uses Supabase-backed project APIs; sandbox execution and media rendering are intentionally disabled for the current development configuration.

## Access and persistence rules

All protected write routes check the request origin, verified Supabase identity,
MFA assurance where enrolled, ownership or administrator role, and input limits.
Privileged writes and exposed mutation RPCs remain service-owned. Public links
contain revocable expiring capability tokens; legacy encrypted snapshots cannot
be mistaken for empty source snapshots. Database transactions protect file
compare-and-swap saves, project admission limits, chat mutations, plan changes
and Nest removal. Private assets are not placed in public Storage buckets.

## Deferred or externally configured services

Sandbox provisioning, terminal execution, AI generation and media rendering
are excluded by the user's instruction. Google OAuth needs a configured Google
provider in local Supabase. Stripe uses the existing test credentials, with
webhooks forwarded by `pnpm dev:stripe`. AI-provider and legal-document setup
panels retain their existing setup-only state; they do not claim that an AI
provider was activated or that a policy draft was published.
